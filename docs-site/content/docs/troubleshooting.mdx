---
title: Troubleshooting
description: The mornings that go wrong, and what each one is telling you.
---

Start every debugging session in two places: the **run report** at the end
of the edition (the editorial view) and `logs/press-YYYY-MM-DD.log` (the
mechanical view). The press is designed so the 6 a.m. question is answered
by reading, not by stack-trace archaeology. `eto doctor` checks most of the
below in one pass.

## The press stalls

**Symptom:** `PressStalled` after repeated five-minute composite timeouts.

**Almost always:** something else is using the GPU. The compositor needs the
whole card; a speech-to-text sidecar or second model server sharing VRAM
slows one composite call by 100× and the press stops loudly rather than
print a hollow edition. Stop the other workload, or schedule around it.
This failure once printed a 0-story edition — that class of silent failure
is designed out; the loud stop is the fix.

## No edition this morning

Check in order:

1. **`logs/press-…`** — did the run start at all? A scheduler that didn't
   fire is an OS problem; `eto schedule --yes` reinstalls.
2. **`BriefAlreadyPublished`** — a retry reaching this guard is a morning
   that already finished. Not an error.
3. **The quiet page** — an edition that says *nothing to print today* is an
   honest edition: no event was covered by two or more of your sources.
4. **A NoEdition note** (desk papers) — the desk held nothing new. The
   press rested, on purpose.

## A model error

- `ModelMissing` — `eto models pull` downloads the tag's current build from
  the registry. If that build's digest differs from your lock, the next
  print reports `ModelDrifted` instead.
- `ModelDrifted` — a model no longer matches the lock: something updated
  it underneath you, or a fresh pull landed a newer build; `eto models status`
  shows which. A pull cannot restore an older digest, so the way forward is
  `eto models pin`, run deliberately, once you have accepted the new build.
- `OllamaDown` — `eto press` tries to start Ollama itself (only for engines
  that use models); `eto print` and `eto doctor` do not. Start it the way
  your OS expects (app, service, `ollama serve`).

## A feed keeps failing

`FeedUnreachable` with a 403 or 404 is a closed front door, not a flaky one
— the press will not disguise itself to get in. Watch the feed-health line
for a week; a persistent refuser is a candidate for
[replacement from the same side of the aisle](/docs/guides/editing-sources).
Timeouts and 5xx retry themselves.

## TOML gotchas

- **A flag below a `[[source]]` block** belongs to that source; the press
  refuses known flags there by name. Keep paper-wide flags at the top of
  the file.
- **Encoding** — a UTF-8 BOM (some Windows tools add one when rewriting a
  file) is tolerated and stripped on read. Re-encoded punctuation is not;
  the masthead loader reports the exact line of anything it cannot parse.

## The funnel tripped

`FunnelAnomalous` or `VerdictsSuspicious` mean the morning's *distribution*
looked broken — zero candidate pairs from hundreds of items, or a hundred
unanimous verdicts. These abort before model time is wasted. The usual
causes: a prompt edit, a model swap, or a source list reduced to outlets
that never overlap. The run report's funnel line shows where the numbers
fell off a cliff.

## Email didn't send

- `email_edition` still `false`, or the domain identity hasn't verified.
  Until it does, sends go from `[mail] from_fallback` with a note in the
  log; if that is empty too, the verb exits 1 with *no mail identity
  configured*.
- The sent-guard: an edition emails once. `eto email --test you@…` sends
  the latest published edition to one address without touching the list;
  `--test success`, `--test bounce`, `--test complaint` address the SES
  mailbox simulator, so the plumbing can be exercised without a real
  inbox.

## Still stuck

Every error in the log is in [the error reference](/docs/reference/errors)
with its meaning and blast radius. If you hit one that isn't, that is a bug
in the press — the catalog is exhaustive by intent. Open an issue with the
log line.
