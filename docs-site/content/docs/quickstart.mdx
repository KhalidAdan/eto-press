This page takes you from nothing to a printed edition. If you want the full
requirements first, see [Installation](/docs/installation).

## Print your first edition

<Steps>
  <Step title="Initialize a paper">
    ```bash
    npx @eto-press/cli init
    ```
    The wizard asks five questions — name, motto, web address, accent
    color, engine — and writes the paper: `eto.toml`, `sources.toml` seeded
    from the audited AllSides shelf, `.env.example`, `.gitignore`. Nothing
    else happens yet; it ends by printing the commands that follow.
  </Step>
  <Step title="Install the press into it">
    ```bash
    npm init -y && npm install @eto-press/press @eto-press/cli
    ```
    From here on, `eto` runs from the paper's own `node_modules`.
  </Step>
  <Step title="Pull the models">
    ```bash
    eto models pull
    ```
    Downloads the judge and the compositor into Ollama and pins their
    digests to `models.lock.json` — generated, never hand-edited. Skip
    this for a desk paper.
  </Step>
  <Step title="Check the press">
    ```bash
    eto doctor
    ```
    Preflight as a command: Ollama reachable, models matching the lock, no
    foreign models resident on the GPU, feeds answering, the last edition's
    status.
  </Step>
  <Step title="Print a morning">
    ```bash
    eto press
    ```
    The whole morning as one verb — print the edition, render the site,
    export the journal, send the email (if configured), take the backups.
    Expect twenty to forty minutes on the first run while the judge works
    through the morning's pairs; reruns resume from the journal.
  </Step>
  <Step title="Make it a habit">
    ```bash
    eto schedule --time 05:30 --yes
    ```
    Installs the morning into your operating system's scheduler — Task
    Scheduler on Windows, launchd on macOS, cron on Linux. Without `--yes`
    it only prints what it would install.
  </Step>
</Steps>

Your edition is now three things at once: a markdown file in `archive/`
(the permanent record), a web page in `site/` — styled and self-contained,
no build step of yours — and, if you climb the [tier ladder](/docs/tiers),
an email in your readers' inboxes.

## What just happened

The wizard created a **paper**: an ordinary directory holding your masthead
(`eto.toml`) and your editorial line (`sources.toml`). The first print added
the journal (`db/`); the first edition added the archive. The press visits
that directory each morning, prints, and leaves. Everything in it is yours —
see [What is a paper?](/docs/concepts/paper)

While it printed, the press fetched every feed through the front door with an
honest user-agent, asked a small local model which items describe the same
event, clustered the matches, selected the broadest stories, fetched the full
accounts, composited each story from outlets that disagree, and then checked
every quote and the sources line against the fetched text before letting it
ship. The whole walk is in [The pipeline](/docs/concepts/pipeline).
