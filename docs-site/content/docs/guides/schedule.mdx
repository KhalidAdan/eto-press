---
title: The paperboy
description: The paper prints itself before you wake.
---

`eto press` is the whole morning as one verb: print the edition, render the
site, export the journal, send the email, take the backups. `eto schedule`
installs it into your operating system's scheduler so it runs before you
wake:

```bash
eto schedule --time 05:30 --yes
```

Without `--yes` it prints the plan for your platform and installs nothing;
with it, it installs exactly that. Task Scheduler on Windows (the job retries
hourly for six hours), a launchd agent on macOS, a crontab line on Linux
(cron only — no systemd unit — and the line tees the morning to
`logs/cron.log`).

## The morning's order

1. **Print** — the pipeline, skipped if `archive/<today>.md` already
   exists. Fatal.
2. **Render** — the public site, from the journal. Fatal.
3. **Export** — the journal's own tables to diffable JSONL (non-fatal).
4. **Email** — the edition to your list, guarded against double-sends
   (non-fatal; the guard makes retries safe). `--no-email` skips it.
5. **Backups** — the journal snapshot, then the reader list. Both
   non-fatal; the reader snapshot runs whatever the tier and fails quietly
   without AWS credentials.

Fatality mirrors the pipeline's rule: a failed *print* or *render* stops
the morning loudly; a failed export, email, or backup logs and continues —
the tail steps are all idempotent, so the next run finishes whatever this
one couldn't.

For a paper whose engine uses models (eto), `eto press` first checks that
Ollama answers and starts it if not. A desk, letter, digest, sports, or wrap
paper never needs Ollama, and the check is skipped.

## Retries are the design

If the press stalls at minute 28, the journal holds everything already done.
The Windows job already retries hourly; on macOS and Linux, add a second
scheduled time if you want one. A completed morning skips the print (the
archive file exists) and reruns the idempotent tail; a partial morning
*finishes* instead of starting over. Recovery is always the same command.

## Logs

Every morning appends to `logs/press-YYYY-MM-DD.log` — the same lines that
went to stdout, so the 6 a.m. question ("why is there no edition?") is
answered by reading one file. The run report inside the edition answers the
editorial version of the same question.

## One machine, one press

The pipeline wants the GPU to itself at press time. If your machine also
serves other models — speech-to-text, a second LLM — schedule around them or
stop them for the morning window; a starved compositor stops the press
loudly rather than printing a hollow edition. See
[Troubleshooting](/docs/troubleshooting#the-press-stalls).
